Changelog — CHOMP

All notable changes to CHOMP are recorded here, newest first. The format follows Keep a Changelog. Versions follow Semantic Versioning.

Rule. Every change is logged here in the same pass as the code, together with the matching updates to the white paper, the deck, and the technical documentation. A prior conclusion is never silently rewritten; what changed and why is stated. The top version here must match the plugin @version stamp.

[3.0.0] — 2026-10-13

Changed

  • CHOMP is now the Reg M-C team-preview solver inside ABRA. The README, white paper, technical documentation, plain-English deck, executive summary and llms.txt are rewritten to describe CHOMP v1 (ABRA solver/chomp/v1/, abra/regmc 1.25.0): both open sheets in, a mixed strategy over the 90 bring-and-lead options out, scored by a learned cell model and solved exactly by linear programming, live at preview in ABRA's ladder client ROTOM. Why: Will asked for the CHOMP project to describe the CHOMP built inside ABRA. The ABRA repository is public, so the documents link its files.
  • Deck slide 6 is rebuilt. It paired a Reg M-B sandstorm anecdote with three figures that did not measure the tool. It now tells the v0-failed / v1-passed story and shows three measured figures, each stated in the white paper with its source (see Record). Why: Will: "this chomp deck slide makes no sense". The whole deck was checked the same way, and tests/test-deck-figures.js now enforces it.
  • The deck's last slide links the rendered white paper; it linked https://github.com/.
  • build/build_deck.js writes to docs/ relative to the script; it wrote to a dead sandbox path.
  • CLAUDE.md states that CHOMP's code lives in ABRA and that the engine and build rules apply to the retired tool only.
  • docs/VALIDATION-REPORT.md carries a banner: it measures the retired Reg M-B userscript.

[2.5.0] — 2026-07-31

Fixed — every build in build/ was unrunnable, which is why the data froze

build/build_lab.js read /tmp/champ_dex.json, /tmp/champ_megas.json and /tmp/champ_moves.json and wrote to /sessions/kind-fervent-sagan/mnt/outputs/. build_v2_userscript.py and build_replay_app.py each carried four absolute paths into that same sandbox mount. Three temp files that were never version controlled, plus a session directory that no longer exists — so the species table beneath champions-damage-lab.html → engine/champ-model.js → the shipped userscripts could not be regenerated by anyone, including its author. Nobody noticed the data ageing because nobody could re-run it to find out.

Measured: the shipped plugin carried 289 species and 57 mega formes against ABRA's 308 and 76. Nineteen mega formes were absent from the species table entirely — starmie-mega, meganium-mega, chimecho-mega, froslass-mega, emboar-mega, excadrill-mega and thirteen others could not be looked up at all.

CORRECTION, recorded rather than quietly fixed. An earlier draft of this entry and of commit ced6137 claimed the plugin had "no abilities at all" and that "every mega was a stat block with no identity". That was wrong. data/mega-formes.json carries a by_item stone table with the ability for all 95 stones, and buildMon applies it (if(!ab && mf.ab) ab = mf.ab) — 75 of the 76 megas in the current dex resolve an ability through it. Mega identity was working. The error came from testing only the first 5 KB of the MONS literal and generalising.

What is true: the MONS table itself carried no ab field (0 of 289), and the 306 now added there are inert — engine/champ-model.js never reads mon.ab, only set.ability from the paste and mf.ab from the stone table. They are carried for future consumers, not because anything reads them today. The real defect fixed here is the 19 missing formes, not missing abilities.

A second silent empty. build_v2_userscript.py's threat list pointed at an absolute ABRA path that could never resolve, so it has been shipping {"threats":[]}. The plugin's threat awareness was not stale, it was empty. It now resolves relative to the repo and prints which case it took, because a fallback indistinguishable from success is how this survived unnoticed.

Added

  • build/refresh_dex_from_abra.js — vendors ABRA's validated dex into data/champ-dex.json with provenance stamped inside it (source commit, date, counts). CHOMP still builds standalone; only refreshing needs the sibling repo, which is the difference between a vendored input and a dependency. Move display names come from ABRA's tags.json, because title-casing an id cannot recover "High Horsepower".

After: 308 species, 76 mega formes, 306 with an ability, 500 moves with real names.

A bug introduced during this work, caught by the tests

ABRA encodes move category as 'P'/'S'; CHOMP's engine tests mv.c === 'Physical'. Passing that encoding straight through meant phys was never true — Intimidate silently stopped firing and every damage number came off the wrong attacking stat. test-damage-golden.js still passed 16/16, because none of its cases distinguishes physical from special; test-engine.js caught it on the one that does. Two artifacts agreeing on a field name while disagreeing on its values type-checks and then lies. Category is now translated at the boundary.

Both suites green: test-engine 4/4, test-damage-golden 16/16.

The plugin now ships the current dex — patched surgically, not regenerated

build_v2_userscript.py emits version 2.4; the shipped chomp-bring4.user.js is 2.8. A diff shows regenerating it loses ten functions — liveMon, readField, mkMon, refresh, realMoves, renderMoves among them: the entire Showdown bridge that reads a live battle.

Versions 2.5–2.8 were written directly into the built .user.js and never went back into the builder or this changelog. The shipped plugin has diverged from its own build system, and this file being four versions behind is the visible symptom — the rule at the top says the top version must match the plugin's @version stamp, and it has not for four releases.

Regenerating would have replaced four versions of the live bridge with an older template and called it an update. So build/patch_plugin_data.js replaces only the MONS and MOVES literals and touches nothing else. It refuses unless it can verify, before writing: the eight bridge functions are present both before and after, the patched file parses as JavaScript, and no move carries ABRA's P/S encoding — the mismatch that silently disabled Intimidate earlier in this same change.

Shipped: chomp-bring4.user.js v2.8 -> v2.9. MONS 34,214 -> 64,689 bytes, MOVES 20,047 -> 32,921. 19 mega formes that could not previously be looked up are now present. The 306 ab fields are carried but inert (see the correction above). Bridge verified 6/6 after write.

The underlying divergence is not resolved: the builder still emits 2.4 and still does not contain the bridge. Porting 2.5-2.9 back into build_v2_userscript.py remains outstanding, and until it is done this patch script is the only safe way to ship data.

Also found

.git/index.lock was seven days old with no git process holding it — a crashed auto-commit on 2026-07-24. That is why this repository's previous commit was 2026-07-24 and why champ-model.js, tests/test-mega-and-boosts.js, build/build_move_effects.js, data/move-effects.json and tests/test-engine-contract.js all carried stranded changes from that same day. The auto-commit timer had been failing silently for a week. Removing the lock caused that timer to immediately commit and push everything as 68d2371 "auto: Fri 07/31/2026 1:39:46.67" — this entry is the record of what that commit actually contains, since its own message says nothing.

[2.4.0] — 2026-07-22

Added

  • ABRA meta model embedded in the plugin (the flow-back loop). The built plugin now carries CHOMP_META, the ladder usage model from the separate ABRA project, and can compute the opponent's likely four — their best four against your six (bring4(theirSix, yourSix)), ABRA bring-rate as fallback prior. This is advisory intel, not a constraint on your pick.
  • The bring itself covers the opponent's whole six, deliberately. You cannot know which four they will bring, so CHOMP picks the four that answer all six — coverage over a gamble on a prediction. ABRA tells you what they will probably do; the pick keeps you safe if they don't.

Pinned by tests/test-meta-flow.js (5 tests) and verified on a real battle. Because CHOMP auto-updates from GitHub, a fresher ABRA model reaches the live plugin with no manual step.

[2.3.0] — 2026-07-22

Added

  • Operation Ladder foundation — ladder-wide meta model. build/meta-ingest.js pulls public replays for the format (any players, paginated) and aggregates both sides into data/meta-usage.json: team%, bring%, lead% and win% per species. Tested on 302 teams from 151 real ladder replays; the result reproduces the hand-curated threat list. This is the shared data layer that grows unattended and will feed the pick-4, the dashboard, and the team optimiser.

Changed

  • Panel stripped to the decision only. It now shows two lines — LEAD (the two to send out) and BRING (the four to pick) — and nothing else. Removed the per-Pokémon damage bars and percentages, the weather/score line, and the 6/6 real sets line, on the user's request for the smallest possible panel. The full damage math still runs underneath to choose the four and the two; it is simply no longer printed.

[2.0.0] — 2026-07-22

Added

  • Move-legality oracle. data/champions-legal-moves.json (49 KB), generated from the HoopaDex export champions-learnsets.json: one bitmask per species over 496 moves, per regulation. Small enough to inline in the userscript.
  • canLearn(species, move, regulation) in engine/champ-model.js, wired into the synthesis filter in both build scripts.
  • tests/test-legality.js (16 tests).

Changed

  • Synthesized opponent sets now respect the Champions legal-move list. The engine used to take the strongest move of the right category from the whole table without checking the learnset — this is how Charizard was once given Eruption. Measured effect: Charizard's synthesized set changed from Eruption to Overheat / Hurricane / Focus Blast. Every synthesized set checked is now legal.

Fixed

  • Undefined isBannedItem in the built userscript. The build sliced the engine from const byName, which starts after that definition, so the banned-item check would throw a ReferenceError on the first parsed set. The slice now starts at const FORMAT. Verified by loading the built file.

Notes

  • Safety rule. The oracle answers "is this pair recorded as legal", not "is this pair illegal". Five moves in the legal pool (spore, softboiled, milk drink, power shift, struggle) are absent from the export. Anything absent is ALLOWED. A missing datum must never delete a real move.
  • Domain note. Champions has no level-up movesets and no TM items. The methods field holds ["TM"] for all 14,192 pairs and carries no information. A Scarlet/Violet moveset is not a guide to Champions legality — Garchomp learns Surf in Champions but not Waterfall.
